# Issue Tracker

This repository uses **GitHub Issues** as the source of truth for product decisions that need implementation, specifications, bugs and engineering tasks.

## Rules

- Repository: `gyguan/harmonyos-homework-assistant`
- New feature discussions should end in one parent spec issue or a small set of implementation issues.
- Bugs should include reproduction steps, expected behavior, actual behavior and device/window context when UI-related.
- Phone/Pad responsive behavior must be explicit in UI-related issues.
- Privacy/security-sensitive work must state what student or family data is touched.
- Pull requests implement issues; they are not the primary requirements store.

## Recommended issue lifecycle

`idea/discussion → clarified → spec-ready → implementation → review → done`

If the `triage` skill is introduced later, its label vocabulary should be documented separately instead of changing the lifecycle implicitly.
