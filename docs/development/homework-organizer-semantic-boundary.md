# 作业整理：AI 语义边界与通用质量门禁

## 本次整改范围

为了实现家长反馈后的自主学习，不再使用 Java 为各个老师的简称、作业类型或者数值关系编写专项兜底。原有整理器在模型输出之后通过关键词修改学科、提取篇名填标题、按简写重新拆分以及删除绘本任务，这些均可能覆盖新反馈产生的 AI 经验。本次移除运行时这几类语义重写；**不是移除业务约束**。

- **模型 + 数据库规则**：决定学科归属、原文简写含义、任务是否属于需要创建的作业、如何拆项以及标题要求。全局词典和场景模板仍由 V40 的 `homework_organizer_rule` 管理，家长反馈经验由 V42 的 `homework_teacher_experience` 管理，停用后不再使用。
- **Java 通用门禁**：字段/schema 校验、合法 subject 值、标题非空、字段长度、日期/时长范围、数字序号结构性防漏拆、原文证据存储、家庭和学生隔离。模型输出存在不合法学科或标题时直接拒绝这一批不完整结果，不通过关键词擅自修改或静默删掉部分任务。
- **AI 质量复核**：当前学生已匹配的启用经验存在时，再调用一次模型以当前原文、首轮结构化结果和适用经验作语义核对；第二轮输出同样接受 schema、非空及不少于初稿任务数的检查。如果复核失败，保留第一轮可编辑候选，不执行 Java 专项改写。
- **界面体验**：用户不必配置触发词、不必理解正则；反馈成功入库后下次动态加进整理 Prompt。二次 AI 复核只对命中经验的请求触发，会增加该请求的时延和 token，普通没有匹配经验的请求仍为一次模型调用。

## 回归原则

1. 模型若输出“完成摘抄（3+2）”，Java **不能**自行写成“3 个好词、2 个好句”；只有启用的确认经验和 AI 复核才能产生这种语义变化。
2. 如果模型把学习进度误输出为作业、把绘本任务误输出为重复语音任务，Java 不应按业务关键词偷偷删除。这需要依靠当前数据库规则、AI 主轮或复核纠正，并在真实模型验收时重点检查。
3. 字段非法、标题空或输出某条不合法时不返回部分成功数据，以免家长误以为原文中的其他条目已经全部覆盖。
4. Java 仍可对清晰编号 1、2 等的结构性合并作通用拆分。该机制不推导课本篇名、简写含义、学生身份或业务归属。
5. 禁用经验后不再触发该经验的复核；不能因为模型复核失败就声称已按经验完成校正。

## 验证

- `ConfigurableHomeworkOrganizerModelClientTest` 验证转换不因“绘本、学习进度、摘抄”等词改写业务含义，并用模拟 AI 证实下一轮可把“摘抄（3+2）”转换为经验指导的标题；第二轮异常不触发 Java 业务兜底。
- `scripts/validate_organizer_semantic_boundary.py` 固定职责边界，防止后续迭代偷偷加回关键词转换器。
- CI Java、Static Gate、PostgreSQL E2E 验证工程及旧功能契约。外部实际模型的语义可靠性和复核效果需实际环境对照样本测试；**单测使用的 Mock AI 不能证明真实模型一定理解正确**。

本次不修改数据库表或新增 Flyway 迁移，也不调整已有规则的启用状态。
