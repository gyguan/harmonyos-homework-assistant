# V0.1 单家庭产品收敛基线

## 一句话定位

**小伴作业是一个家庭的 AI 作业管家：家长负责把老师作业带进来，孩子只管完成，小伴负责整理与辅导，家长最后看结果。**

## 三个核心动作

### 1. 收作业

用户主动提供老师内容：

- 微信/钉钉截图
- 粘贴文本
- PDF / Word / PPT
- 系统 Share

经过：

`原始内容 → TextExtractor → AssignmentParser → CandidateAssignment → 家长确认`

AI 的职责是减少录入，不直接发布作业。

### 2. 做作业

学生端遵循：

> 不让孩子管理作业，只让孩子完成作业。

首页首先回答“我现在应该做什么？”，再展示今天其他任务。

学习过程中可进入 AI Tutor；默认引导优先，不直接代做。

### 3. 看进度

家长首页不做管理大盘，只回答：

- 今天一共几项？
- 已完成几项？
- 哪项正在做？
- 哪项还没开始？
- 是否已经提交？

## V0.1 核心对象

- `StudentProfile`：当前孩子基本信息；
- `CandidateAssignment`：AI 整理、待家长确认的作业；
- `Assignment`：家长确认后进入孩子执行清单的作业；
- `Submission`：孩子提交的作业成果；
- `TutorSession`：与具体 Assignment 关联的辅导会话最小记录；
- `AppSettings`：教材/辅导策略等家庭设置入口。

V0.1 不显式建立：

- Family
- Parent
- Guardian
- Teacher
- School
- Class
- Organization

## 页面主线

### 学生模式

`今天 → 作业 → 我的`

“教材”不作为一级导航，教材上下文属于 Assignment / Tutor 的支撑信息。

### 家长模式

`首页 → 导入 → 进度 → 我的`

首页保持简单：今日完成度 + 作业状态 + 导入老师作业。

## 技术边界

只保留必要层次：

```text
ArkUI Pages
    ↓
HomeworkStore / HomeworkService
    ↓
Persistence Port / AI Port
    ↓
Preferences / OCR / LLM Adapter
```

保留：

- `HomeworkPersistence`
- `HomeworkTextExtractor`
- `HomeworkAssignmentParser`

不引入：

- 微服务
- Gateway
- Event Bus
- CQRS
- Workflow Engine
- 多租户模型
- 复杂 Repository / UseCase / Handler 分层

## V0.1 成功标准

完整跑通且家庭愿意每天使用：

`老师消息 → 自动整理 → 家长确认 → 孩子完成 → AI 辅导（可选）→ 提交 → 家长看到结果`

任何不能直接改善这条主链路的功能，默认不进入 V0.1。
