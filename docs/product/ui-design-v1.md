# 小伴作业｜UI 设计 V1（正式方向）

> 基于 `prototype/ui-v1` 三个方案收敛：**A 作为总体交互骨架，B 作为 Pad 学习工作台，C 仅提取儿童友好的视觉与文案表达**。

## 1. 设计结论

### 学生端

- Phone：采用 **Focus Journey**，强调“下一项作业”和单任务执行。
- Pad：采用 **Learning Desk**，把“任务 / 当前作业 / AI Tutor”同屏呈现。
- 视觉：使用 C 方案的柔和圆角、学科色和友好文案，但不引入积分、排名、过度游戏化。

### 家长端

- 采用 A 方案的克制信息结构。
- 首页只回答：今天有多少作业、完成多少、正在做什么、是否需要家长介入。
- 导入页面在 Pad 上使用“原始内容 + AI 解析结果”双栏，并展示 Source Evidence。

## 2. 视觉原则

1. **孩子端少管理、多行动**：每个页面只突出一个主动作。
2. **家长端少装饰、多状态**：强调进度、异常、证据和确认。
3. **Phone 不做桌面化**：不强塞多栏信息。
4. **Pad 不放大 Phone**：利用宽屏展示主从、资料 + 辅导、原文 + 解析等关系。
5. **儿童友好但不幼稚**：颜色柔和、文案正向、避免强刺激和竞争性机制。
6. **AI 始终可解释**：解析结果提供来源证据；辅导优先给提示而不是直接答案。

## 4. 学生端核心页面

### S01 Today

**目标**：让孩子打开 App 后立即知道现在该做什么。

内容优先级：

1. 下一项作业
2. 今日完成度
3. 今日其他作业
4. 即将到期提醒

主动作：`开始 / 继续完成`

Phone：单列。
Pad：左侧任务列表 + 右侧当前任务摘要。

### S02 Assignment Detail

内容：

- 学科、标题、截止时间
- 老师要求
- 关联教材
- 老师附件
- 预计用时

主动作：`开始作业`

### S03 Study Workspace

这是学生端核心页面。

Phone：

- 当前作业
- 老师资料
- AI Tutor 入口
- 提交入口

Pad > 840vp：

```text
┌──────────────┬──────────────────────┬─────────────────┐
│ 今日任务       │ 当前作业 / 老师资料      │ AI Tutor        │
│              │                      │                 │
│ ✓ 语文        │ 题目 / PDF / 视频       │ 提示 / 追问      │
│ ● 数学        │ 教材关联               │ 分步讲解         │
│ ○ 英语        │                      │                 │
└──────────────┴──────────────────────┴─────────────────┘
```

建议比例：20% / 50% / 30%。

### S04 AI Tutor

输入方式：

- 文字
- 语音
- 拍题

辅导层级：

1. 理解问题
2. 轻提示
3. 下一步提示
4. 分步讲解
5. 完整解释
6. 检查理解

默认不直接代做。

### S05 Submission

首版重点支持照片提交：

- 连续拍照
- 清晰度提示
- 顺序调整
- 删除重拍
- 提交确认

后续扩展录音 / 视频。

## 5. 家长端核心页面

### P01 Dashboard

核心区：

- 今日完成率
- 已完成
- 进行中
- 未开始
- 超时 / 需关注

Pad 右侧可展示本周趋势和需关注事项。

### P02 Import

入口：

- 微信 / 钉钉主动分享
- 聊天截图
- 粘贴文本
- 上传文档 / 图片 / 音视频
- 手工创建

Pad：左边原始内容，右边解析结果。

### P03 Homework Confirmation

每个 Candidate Assignment 显示：

- 学科
- 标题
- 截止时间
- 老师要求
- 关联教材
- Source Evidence
- 解析置信提示（仅低置信时突出）

动作：修改 / 拆分 / 合并 / 删除 / 发布。

### P04 Progress

展示每个作业：

- 状态
- 开始时间
- 当前耗时
- 提交时间
- 是否使用 AI Tutor
- 是否需要家长介入

### P05 Submission Viewer

家长可查看孩子上传的照片 / 录音 / 视频，但首版不要求家长评分。

## 6. 响应式规则

以**当前窗口宽度**而不是设备型号决定布局。

### Compact：≤ 600vp

- 单列
- 底部导航
- 列表点击进入详情
- 主要按钮全宽

### Medium：600–840vp

- Pad 竖屏 / 分屏典型范围
- 左侧导航
- 主内容以单列为主
- 局部双列

### Expanded：> 840vp

- 左侧导航
- 列表 + 详情主从分栏
- 学习工作台三栏
- 家长导入双栏
- Dashboard 多卡片布局

HarmonyOS 官方 `SplitLayout` 本身即按 ≤600vp、600–840vp、>840vp 三档适配，可优先用于详情类场景；复杂页面使用 `Navigation + GridRow/GridCol + ContainerReader` 组合。

## 7. 设计 Token 建议

### 色彩

- Brand Primary：`#2F6BFF`
- Success：`#20A66A`
- Warning：`#F59E0B`
- Danger：`#E5484D`
- Text Primary：`#182230`
- Text Secondary：`#687386`
- Surface：`#FFFFFF`
- Background：`#F5F7FA`

学科色只做辅助识别，不承担状态含义。

### 圆角

- 小控件：10–12vp
- 卡片：16–20vp
- 大面板：20–24vp

### 间距

以 4vp 为基础单位：8 / 12 / 16 / 20 / 24 / 32。

### 触控

所有主要触控目标保持足够尺寸，不因 Pad 信息密度增加而缩小。

## 8. 页面状态统一规范

每个页面至少设计：

- Loading
- Empty
- Normal
- Partial / Degraded
- Error
- Offline（需要时）

AI 相关页面额外设计：

- Parsing
- Needs Confirmation
- Low Confidence
- AI Unavailable

## 9. V0.1 首版视觉验收

满足以下条件才算 UI 可进入开发：

- Phone / Pad 均有明确布局，不存在简单拉伸。
- 学生端 5 个核心页面完整。
- 家长端 5 个核心页面完整。
- Study Workspace 在 Pad 上具备三栏布局。
- Import / Confirmation 在 Pad 上具备原文与结果并排能力。
- Source Evidence 能从解析结果回溯老师原内容。
- 所有关键页面具备空态、加载态和异常态。
