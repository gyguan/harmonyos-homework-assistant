# Issue #478｜第九批合并后审查 P2 证据展示整改（2026-10-09）

## 根因

PR #493 对新版两套模考的72道派生 Part7 做上下文审阅，确认4道题的**保存版证据字段**缺少解题必需的跨文档条件，而完整阅读文章和既有答案仍可互相验证。

旧质量门禁仅要求把“缺口”保留在台账里，仍可输出整体 PASS，不满足“学习端展示的证据确实足以证明答案”的发布标准。PR #493 合并后代码评审明确指出这一 P2。

## 解决方案：补足真正展示的证据，不破坏历史数据

新增共享 `ToeicEvidenceDisplayService`，维护经过逐字核验的4道原文补充证据。服务从旧保存版的 `question.evidence` 出发，追加每个答案必要、但被旧摘要省略的原文片段，绝不在运行时用模型临时猜证据。

| 现行题号 | 补足的跨文档证据 |
|---|---|
| `R-FM1-P7-M1-01` | 演示前须预留20分钟步行；结合52/60车到站时间与9:15演示开始时刻 |
| `R-FM1-P7-M4-01` | 公交到Downtown后需约10分钟步行；结合8:40/9:10班次与9:00开会 |
| `R-FM2-P7-M1-01` | 须至少比9:15会议提前20分钟到Central站；结合88/94/102到站时刻 |
| `R-FM2-P7-M5-03` | 除物流经验外，还要校验电子表格能力证明和9月15日前到岗要求及邮件承诺 |

`ToeicHomePage` 的**当前题目证据快照、练习结果列表、历史模考回放**均统一调用相同的展示服务。模考作答过程仍然不能看即时证据或解析，只有交卷结果页呈现完整证据。

历史保护：保留现有题目ID、题目版本、四个选项、正确答案、审核原始源码哈希和全部存量答题记录。未提升已保存的旧内容版本，也不直接更改旧 `ToeicMockDay14/19V2Content.ets` 静态题目。

## 发布门禁升级

`scripts/validate_toeic_v2_derived_part7_editorial_issue478.py` 必须确认：

- 4道题的**所有必需引文**均真实出现在其当前阅读组原文、确实未出现在原始不完整高亮、且都已纳入新的实际显示文本；
- 仅存在这些4条有出处的审校补全资产，不允许数据中重复或遗漏；
- 当前题目、练习结果、历史模考回放**三个实际UI调用点**都接入同一展示服务；
- 未补充证据的情况下，不能声明完成修复；保留负向答案篡改和原始审校台账版本校验；
- 保留4条历史缺口的审校事实，同时标记 `learnerPresentationUnresolvedGaps=0`，不把缺口隐藏掉。

这属于“证据展示层的可追溯编辑补全”，而不是原先“已知证据缺口也允许发布”的例外。自动校验与正式App编译是两个层级：即使CI静态门禁通过，也不宣称鸿蒙SDK编译或Phone/Pad真机验证通过。
